# Eval вердиктов DietHelper

Проверяем, насколько верно прод-код (`diet/gemini.py`, модель `gemini-3.1-flash-lite`, структурированный вывод по Pydantic-схеме `Answer`) выносит вердикт "Можно / Нельзя / С осторожностью" для пары "диета + блюдо". Прогоны от 30.10.2026, бесплатная квота Gemini API.

## Главное

| Метрика (прод: gemini-3.1-flash-lite, промпт v1, 100 кейсов) | Весь набор | Без спорных (87) |
|---|---|---|
| Accuracy | **77.0%** | **83.9%** |
| Macro-F1 | 0.76 | 0.82 |
| Опасные ошибки (ожидали "Нельзя", ответ "Можно") | **0 из 38** | 0 из 35 |
| Ответ прошёл схему | 100% | 100% |
| Стабильность вердикта на 3 повторах (подвыборка 30) | 93.3% | 92.9% |
| Латентность p50 | 1.6 с | 1.5 с |

Модель ни разу не разрешила запрещённое. Почти все ошибки (21 из 23) лежат на соседних классах: "Можно" против "С осторожностью" и "С осторожностью" против "Нельзя", то есть модель перестраховывается.

## Методика

- **Набор** `eval/cases.jsonl`: 100 кейсов, 11 типов диет (целиакия, непереносимость лактозы, кето, веганство, вегетарианство, гипертония с ограничением соли, диабет 2 типа, аллергия на орехи с анафилаксией, low-FODMAP, халяль, подагра). Классы: Можно 34, Нельзя 38, С осторожностью 28. Сложность: easy 51, border 38 (пограничные: пармезан при непереносимости лактозы, мёд для вегана, кокос при аллергии на орехи), ambiguous 11 (блюда с разным рецептом: Цезарь, борщ, песто, окрошка, шаурма). Источник набора `eval/build_cases.py`.
- **Разметка** по общепринятым правилам (Vegan Society, Monash low-FODMAP, ADA, ACR 2020 по подагре, ВОЗ по соли), правило записано в поле `rationale`. Соглашение: "Нельзя", если классический рецепт нарушает диету; "С осторожностью", если допустимо только малой порцией, рецепт бывает разным или всё решает состав конкретного продукта; "Можно", если обычный рецепт в обычной порции подходит.
- **Спорные кейсы** (`disputed: true`, 13 штук), где разумные диетологи разойдутся: овёс при целиакии, сливочное масло и сырники при непереносимости лактозы, песто для вегана, пармезан для вегетарианца, грибной суп, гречка и мёд при диабете, кокос и арахис при аллергии на орехи, тирамису для халяль, грибы и чечевица при подагре. Метрики даны с ними и без них.
- **Прогон** `eval/run_eval.py` вызывает ту же `get_verdict`, что и прод; модель и системный промпт подменяются параметрами. Ответы кэшируются на диске (`eval/.cache/<модель>/<хэш промпта>/<id>_<повтор>.json`, не в git), повторный запуск не делает запросов.
- **Метрики** `eval/metrics.py`, тесты на синтетике в `eval/tests.py` (идут в CI). Accuracy и F1 считаются по первому повтору каждого кейса. Невалидный ответ (не прошёл схему) считается ошибкой.
- **Подвыборка** `eval/subset30.txt`: 30 кейсов, стратифицирована по классу и сложности, seed 42, все 11 диет. На ней стабильность и сравнения.

| Ожидали \ Ответ | Можно | Нельзя | С осторожностью |
|---|---|---|---|
| **Можно** (34) | 24 | 2 | 8 |
| **Нельзя** (38) | 0 | 34 | 4 |
| **С осторожностью** (28) | 2 | 7 | 19 |

| Класс | Precision | Recall | F1 |
|---|---|---|---|
| Можно | 0.92 | 0.71 | 0.80 |
| Нельзя | 0.79 | 0.89 | 0.84 |

По сложности: из 23 ошибок 5 на easy (из 51), 14 на border (из 38), 4 на ambiguous (из 11).

## Сравнение моделей и промптов (подвыборка 30)

| Конфигурация | Accuracy | Без спорных (28) | Macro-F1 | Опасные | Латентность p50 / p95 |
|---|---|---|---|---|---|
| gemini-3.1-flash-lite, промпт v1 (прод) | **86.7%** | **92.9%** | 0.86 | 0 из 11 | 1.5 / 32.7 с |
| gemini-3.5-flash-lite, промпт v1 | 83.3% | 89.3% | 0.83 | 0 из 11 | 1.3 / 1.9 с |
| gemini-3.1-flash-lite, промпт v2 | 80.0% | 85.7% | 0.79 | 0 из 11 | 1.5 / 7.3 с |

- **Промпт v2** (`eval/prompts.py`: явные правила выбора вердикта и "при неизвестном составе выбирай более безопасный") ухудшил точность: модель чаще ставит "Нельзя" вместо "С осторожностью" (recall "С осторожностью" 0.56 против 0.78). В прод не внедрён, это результат эксперимента.
- **gemini-3.5-flash-lite** немного хуже на этой подвыборке (на 1 кейс, при n=30 это в пределах шума), но заметно стабильнее по времени ответа.
- **gemini-2.5-flash** сравнить не удалось: все запросы вернули ошибку API (не квоту), см. "Ограничения".
- Подвыборка оказалась легче полного набора (86.7% против 77.0% у прода), поэтому сравнивать конфигурации надо между собой, а не с полным набором.

## Характерные ошибки

1. **Перестраховка на безопасном** (8 из 23, "Можно" -> "С осторожностью"): `gf05` рис с курицей и `gf10` кукурузная каша при целиакии ("опасность в соусах, перекрёстное загрязнение"), `fm10` эспрессо с безлактозным молоком при СРК ("кофеин триггер"), `fm07` безлактозный йогурт ("может быть инулин"). Для пользователя это лишняя тревога, не вред, но снижает пользу ответа.
2. **"Нельзя" вместо "С осторожностью" при строгих диагнозах** (7 из 23): `na06` молочный шоколад и `na07` арахисовая паста при анафилаксии, `ls03` фета при гипертонии, `vg05` мармелад для вегана (модель считает, что он всегда на желатине). При аллергии с анафилаксией ответ модели медицински обоснован, разметка здесь спорная.
3. **Неоднозначные блюда в сторону мягкости** (`vg06` борщ, `vg03` песто, `hl03` тирамису): модель сама пишет, что классический рецепт нарушает диету, но ставит "С осторожностью". Ни одна из этих ошибок не стала "Можно".
4. **Устаревшие правила** (`gt06` грибы и `gt08` чечевица при подагре): модель повторяет старый запрет на растительные пурины, хотя ACR 2020 его не поддерживает. Оба кейса помечены спорными.
5. **Ошибка на очевидном кейсе** `fm03` яблоко при low-FODMAP: модель сама перечисляет фруктозу и сорбит, но ставит "С осторожностью" вместо "Нельзя".
6. **Нестабильность** на 3 повторах только в 2 кейсах из 30: `dm04` белый рис при диабете (осторожно, осторожно, нельзя) и `fm04` спелый банан при low-FODMAP (осторожно, можно, осторожно). Оба пограничные.

## Ограничения

- 100 кейсов, разметка одним разметчиком (Claude по опубликованным правилам), без проверки диетологом. 13 спорных кейсов ждут просмотра автором проекта.
- Сравнения на 30 кейсах: разница в 1-2 кейса (3-7 п.п.) статистически не значима.
- Латентность p95 у прод-модели (30+ с) завышена: во время прогона два процесса по ошибке делили минутную квоту, ответы приходили с задержкой на стороне API. p50 и p95 других прогонов (1.3-7 с) ближе к реальности.
- gemini-2.5-flash отвечал ошибкой на каждый запрос (не 429). Причина в логах не сохранилась, раннер теперь пишет текст ошибки в `eval/.cache/requests.log`.
- Запросов к API за прогон: 495, из них 297 успешных ответов; остальное 429 (18) и ошибки gemini-2.5-flash (180). Ограничение в 450 запросов превышено из-за двух одновременно запущенных прогонов; раннер теперь не даёт запустить второй (файл блокировки).

## Воспроизведение

```bash
pip install -r requirements.txt
export GEMINI_API_KEY=...            # или --env-file путь/к/.env
python -X utf8 -m eval.run_eval --dry-run                                   # сколько запросов нужно
python -X utf8 -m eval.run_eval                                             # 100 кейсов, прод
python -X utf8 -m eval.run_eval --subset eval/subset30.txt --repeats 3      # стабильность
python -X utf8 -m eval.run_eval --subset eval/subset30.txt --prompts v2
python -X utf8 -m eval.run_eval --subset eval/subset30.txt --models gemini-3.5-flash-lite
python manage.py test eval                                                  # тесты метрик
```

Сводки прогонов: `eval/results/*.json` (метрики и вердикт по каждому кейсу).

## Для CV

- Построил eval LLM-классификатора диетических вердиктов: 100 размеченных кейсов по 11 диетам, accuracy 77% (84% без спорных кейсов), 0 опасных ошибок из 38, стабильность 93% на 3 повторах; сравнил 2 модели Gemini и 2 версии промпта.
- Eval показал, что промпт с жёсткими правилами снижает точность с 87% до 80% на подвыборке, поэтому в прод он не пошёл.
